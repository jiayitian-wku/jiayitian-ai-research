# Research Map

## 项目边界

**用户确认的研究方向：** 基于输出长度预测的大模型推理调度。

**当前重点：** 预测输出长度，不是预测输入长度。

**核心研究问题：** 能否利用预测的输出长度，帮助调度器做出更好的调度决策，从而改善大模型推理系统的性能？

## 研究主线

```text
用户请求
  ↓
输出长度预测器
  ↓
预测输出长度（未来可能包含不确定性信息）
  ↓
调度器
  ↓
GPU 资源分配与请求执行
  ↓
LLM 推理
  ↓
延迟、吞吐量、GPU 利用率
```

## 系统分层

### 1. 请求与预测层

- 请求到达时，可以观察输入 prompt，但真实输出长度尚未知。
- 预测器尝试在推理完成前提供输出长度相关信息。
- 预测器究竟应提供点预测、排序、区间还是分布，仍是待研究问题。

### 2. 调度决策层

需要结合真实 serving 系统进一步确认调度器可使用输出长度信息改变哪些决策，例如：

- waiting queue 中的优先级；
- 请求进入 batch 的顺序与组合；
- GPU/KV Cache 资源规划；
- 是否以及何时进行 preemption。

以上是当前问题空间，不代表这些决策都已经被本项目采用。

### 3. LLM Serving 层

当前需要重点理解：

- Prefill 与 Decode；
- KV Cache 的生成与增长；
- 固定 batch 的限制；
- continuous batching；
- vLLM 与 SGLang 中真实的请求执行、调度和内存管理机制。

### 4. 评价层

候选观察维度包括：

- 请求级：waiting time、turnaround time、TTFT、TPOT；
- 系统级：吞吐量、GPU 利用率和显存使用；
- 预测级：数值误差、相对排序以及不确定性质量。

这些目前只是候选维度，正式指标与成功标准尚未确定。

## 已有个人理解与未验证假设

**个人理解：** 预测数值有误差，不一定意味着调度顺序发生变化。例如真实长度和预测长度数值不同，但相对排序仍可能保持一致。

**研究假设：** 对于基于输出长度的调度，相对排序质量可能是区别于绝对预测误差的一个重要因素。

**证据状态：** 该理解来自用户此前的简化 FCFS/SJF toy scheduling 思维实验，尚未经过论文核验或真实 GPU serving 实验验证。
